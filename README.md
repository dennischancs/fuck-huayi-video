#### 🛡️ 倍速检测原理 & CDN 域名依赖

**结论先行：脚本倍速（最高 8x）不会被服务器发现。** 原因如下：

##### 浏览器层：播放器读不到真实倍速
- 脚本在 `document-start` 阶段劫持 `HTMLMediaElement.prototype.playbackRate` 的 getter，**任何代码读 `video.playbackRate` 都会拿到 1.0**，包括：
  - CC 播放器本体（h5player-3.6.2.js）的 `getVideoRate()` 方法
  - CC 埋点 SDK（ccTrack.js v2.6.10，已扫描无 `playbackRate` / `ratechange` 关键词）
  - 页面自身 JS
- 播放器内部**没有** `setInterval` 采样 `currentTime` 算有效倍速的逻辑；它唯一的反作弊是进度条拖拽看门狗（`banDrag`：单次 seek > 2s 且超过已看最大时间 → 强制回退），与倍速无关

##### 服务器层：只盯会话时长，不盯倍速
服务器真正校验的是 **`session 开始时间` vs `session 结束时间`**：
- 倍速 8x 看完 45 分钟课件 → 仅用 5.6 分钟 → 服务器记录"学习中"（时长不够）
- 等待时间 ≥ 视频真实时长 → 时长达标 → 自动记录完成
- 脚本靠**分天策略**解决此问题：第一天倍速标记所有课程，第二天时长达标后直接跳 99% 以 1.0x 匀速跑完

##### CDN 域名依赖（代理用户必看）
CC 播放器运行依赖以下三个域名，**必须加入代理排除规则**（`DOMAIN-SUFFIX` 覆盖所有子域名）：

| 域名 | 用途 | 被代理拦截后果 |
|---|---|---|
